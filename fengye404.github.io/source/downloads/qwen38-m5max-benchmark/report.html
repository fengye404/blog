运行稳定性：原生 mixed 加载共记录 6 次 GPU 超时，发生在权重预计算阶段；最后单独补测三个缺失批次均成功。不能据此认定加载问题已经修复。中途电脑重启一次，随后按检查点恢复；首次记录与后续记录的系统缓存环境可能不同。所有正式速度请求的采样 Swapouts 增量为 0，但系统已有 swap、文件页加载与其他应用仍可能影响时间。

适用边界：输入最高约 261.7K，输出预算仅 256 token，单请求、关闭前缀缓存、关闭思考；未测试长输出、多轮缓存命中、并发服务或复杂长文问答。ngram 采用 SSD mmap，关闭整表主动预热，但 macOS 页缓存没有清空；首轮不能称为受控冷盘。分词诊断通过只读 CPU 接口在两个测速请求期间执行，时间戳保留在核查文件中，未启动额外推理模型；这不是完全隔离的实验环境。

本机启动脚本：start-mixed.sh（默认 MTP）与 start-reap.sh。评测结束后模型服务已停止，内存已释放；脚本的生产缓存设置与本报告的无前缀缓存测试不同。

上下文长度与速度

点为实测中位数，误差棒为各轮最小至最大值；连线仅连接实测点，不代表中间档位已测。MTP 为推测解码模式。各长度的首轮仍可能包含新形状编译、按需文件页加载等开销。

已有记录的独立测试项：240/240；原始速度记录 264 条，含重跑。统计采用每个方案、输入、重复编号的第一条通过核查的记录，额外重跑保留在原始文件中，不重复加权。4 个方案各 60 项。部署检查不计入正式矩阵。

分词核查：相同 tokenizer 文件在 Hugging Face 与原生引擎中的实现存在差异。所有计数异常输入均通过 /tokenize 独立核对，两个 token 序列均可完整还原相同原文，usage 与原生分词数量一致，输入加输出预算未超限。已核实记录按实际引擎 token 数计速并纳入部署对比；这不是完全相同 token 序列下的模型消融实验。核查证据见 tokenizer-audit.json，原始异常标记未修改。

配置与测量口径

两模型均将 n-gram 表保留在 SSD，以 mmap 按需读取；关闭 MLX-Serve 整表后台预热（MLX_SERVE_NGRAM_WARM=0），不强制清空 macOS 页缓存。进程冷启动与真正的 SSD 冷缓存不同。前缀缓存关闭，temperature=0，输出预算 256 token，prefill chunk=1024。相同 tokenizer 与聊天模板，思考模式关闭。

短至 32K 档重复 3 次，64K 及以上重复 2 次；速度表显示中位数（最小–最大）；内存显示各轮最高观测值。重复之间系统文件缓存状态会变化，首轮也不是受控的 SSD 冷缓存。接近 256K 档目标输入为 261,632 token，预留输出空间。输入和输出实际 token 数会保存。不同引擎的对比反映整套部署方案，不能把全部差异归因于剪枝或量化。
